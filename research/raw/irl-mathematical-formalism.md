# Inverse Reinforcement Learning: Mathematical Formalism

## The Forward Problem (Standard RL)

A Markov Decision Process (MDP) is defined as:

**M = (S, A, T, γ, R, s₀)**

Where:
- S = state space
- A = action space
- T(s'|s,a) = transition function (probability of next state s' given current state s and action a)
- γ ∈ [0,1) = discount factor
- R: S → ℝ = reward function
- s₀ = initial state distribution

The goal of RL is to find a policy π: S → A that maximizes expected cumulative discounted reward:

**π* = argmax_π E[Σₜ₌₀^∞ γᵗ R(sₜ) | π, s₀ ~ s₀, sₜ₊₁ ~ T(·|sₜ,π(sₜ))]**

The value function V^π(s) gives the expected return starting from state s and following policy π:

**V^π(s) = E[Σₜ₌₀^∞ γᵗ R(sₜ) | s₀ = s, π]**

The optimal value function satisfies the Bellman equation:

**V*(s) = max_a [R(s) + γ Σ_{s'} T(s'|s,a) V*(s')]**

And the optimal policy is:

**π*(s) = argmax_a [R(s) + γ Σ_{s'} T(s'|s,a) V*(s')]**

This is the forward problem: given R, find π*.

## The Inverse Problem (IRL)

In IRL, we observe expert demonstrations:

**D = {τ₁, τ₂, ..., τₙ}**

where each trajectory τᵢ = (s₀⁽ⁱ⁾, a₀⁽ⁱ⁾, s₁⁽ⁱ⁾, a₁⁽ⁱ⁾, ...) is a sequence of state-action pairs generated by an expert policy π_expert.

The inverse problem: find a reward function R such that π_expert is (approximately) optimal under R.

### The Identifiability Problem

**Critical issue:** The mapping from R to π* is many-to-one. Multiple reward functions can produce the same optimal policy.

Example: If the expert always goes straight, this is consistent with:
- R rewards going straight
- R is constant (all actions equally good)
- R penalizes turning

Without additional constraints, the problem is ill-posed.

## Ng & Russell (2000): Maximum Margin IRL

### Key Insight

Instead of finding any R that makes the expert optimal, find the R that makes the expert's behavior look *most* optimal relative to all alternatives.

### Formulation

Assume the reward is a linear combination of features:

**R(s) = wᵀφ(s)**

where φ: S → ℝᵈ is a feature vector and w ∈ ℝᵈ is a weight vector.

The expected feature counts under policy π starting from s₀ are:

**μ(π) = E[Σₜ₌₀^∞ γᵗ φ(sₜ) | π, s₀]**

The expected return under policy π is:

**V^π = wᵀμ(π)**

For the expert policy π_expert to be optimal, we need:

**wᵀμ(π_expert) ≥ wᵀμ(π) for all π**

Or equivalently:

**wᵀ[μ(π_expert) - μ(π)] ≥ 0 for all π**

### The Optimization Problem

Ng & Russell find w that maximizes the minimum margin:

**max_w min_{π ≠ π_expert} wᵀ[μ(π_expert) - μ(π)]**

subject to ||w||₂ ≤ 1 (to avoid trivial scaling solutions).

This is a convex optimization problem (specifically, a linear program after reformulation).

### Algorithm

1. Initialize policy π₀ (e.g., random)
2. Compute feature counts μ(π_expert) from demonstrations
3. Repeat:
   a. Find w that maximizes margin against all policies seen so far
   b. Find best response policy π_new under reward wᵀφ
   c. Compute μ(π_new)
   d. If margin is small enough, stop
   e. Otherwise, add π_new to the set of policies

This is essentially a cutting-plane method. Each iteration adds a constraint that the expert must be better than the new counterexample.

## Ziebart et al. (2008): Maximum Entropy IRL

### Motivation

Ng & Russell assumes the expert is perfectly optimal. But real humans are not. They make mistakes, have noise in their decisions, and may not be globally optimal.

Maximum Entropy IRL models this by assuming the expert chooses actions probabilistically, with probability proportional to the exponential of the action's value.

### The Boltzmann Rationality Model

The probability of a trajectory τ under the expert policy is:

**P(τ | R) = (1/Z) exp(Σₜ R(sₜ))**

where Z is a normalization constant (partition function):

**Z = Σ_τ exp(Σₜ R(sₜ))**

This is the Boltzmann distribution from statistical mechanics. High-reward trajectories are more likely, but low-reward trajectories still have non-zero probability.

### Key Properties

1. **Smoothness:** Small changes in R lead to smooth changes in P(τ|R)
2. **Uncertainty:** The model naturally handles suboptimal demonstrations
3. **Tractability:** The optimization landscape is better behaved

### The Optimization Problem

Given demonstrations D = {τ₁, ..., τₙ}, find R that maximizes the log-likelihood:

**L(R) = Σᵢ log P(τᵢ | R)**
     **= Σᵢ [Σₜ R(sₜ⁽ⁱ⁾) - log Z]**

Taking the gradient with respect to the reward parameters w (assuming R(s) = wᵀφ(s)):

**∇_w L = Σᵢ Σₜ φ(sₜ⁽ⁱ⁾) - n · E_π[Σₜ φ(sₜ)]**

where the expectation is under the model's predicted policy:

**π(a|s) = (1/Z(s)) exp(Q(s,a))**

and Q(s,a) is the soft Q-function:

**Q(s,a) = R(s) + γ Σ_{s'} T(s'|s,a) V_soft(s')**

**V_soft(s) = log Σ_a exp(Q(s,a))**

Note the log-sum-exp instead of max. This is the "soft" Bellman equation.

### Algorithm

1. Initialize w
2. Repeat until convergence:
   a. Compute soft Q-values and soft values using soft Bellman backup
   b. Compute policy π(a|s) = exp(Q(s,a) - V_soft(s))
   c. Compute expected feature counts under π
   d. Update w using gradient ascent:
      **w ← w + α [μ_empirical - μ_model]**
      where μ_empirical = (1/n) Σᵢ Σₜ φ(sₜ⁽ⁱ⁾)
      and μ_model = E_π[Σₜ φ(sₜ)]

This is essentially gradient ascent on the log-likelihood, where the gradient is the difference between empirical and model feature counts.

### Computational Challenge

The partition function Z requires summing over all possible trajectories, which is exponential in horizon length. For finite horizons, this can be computed exactly using dynamic programming. For infinite horizons, we need approximation methods (e.g., sampling, variational inference).

## Bayesian IRL (Ramachandran & Amir, 2007)

### Motivation

Both Ng & Russell and MaxEnt IRL give point estimates of R. But we want uncertainty estimates. When inferring values, knowing what we don't know is critical.

### Formulation

Place a prior P(R) over reward functions (e.g., Gaussian prior on weights w).

The posterior over rewards given demonstrations is:

**P(R | D) ∝ P(D | R) P(R)**

where P(D | R) is the likelihood (same as MaxEnt IRL):

**P(D | R) = Πᵢ P(τᵢ | R)**

### Inference

We want to compute posterior expectations, e.g.:

**E[R | D] = ∫ R P(R | D) dR**

This integral is intractable, so we use MCMC (Markov Chain Monte Carlo) methods:

1. Initialize R⁰
2. For t = 1, 2, ...:
   a. Propose R* from proposal distribution q(R* | R^{t-1})
   b. Compute acceptance probability:
      **α = min(1, [P(D | R*) P(R*)] / [P(D | R^{t-1}) P(R^{t-1})])**
   c. Accept R* with probability α, otherwise R^t = R^{t-1}

After burn-in, the samples {R^t} approximate the posterior.

### Advantages

- Provides uncertainty estimates (credible intervals on reward weights)
- Naturally incorporates prior knowledge
- Can handle ambiguous demonstrations (posterior will be broad)

### Disadvantages

- Computationally expensive (requires many forward RL solves)
- MCMC convergence can be slow
- Choice of prior matters

## Deep IRL (Wulfmeier et al., 2015)

### Motivation

Linear reward functions R(s) = wᵀφ(s) require hand-engineered features. For high-dimensional state spaces (e.g., images), we need function approximation.

### Formulation

Parameterize the reward function with a neural network:

**R(s; θ) = f_θ(s)**

where θ are the network parameters.

The optimization problem is the same as MaxEnt IRL, but now we optimize θ instead of w:

**max_θ Σᵢ log P(τᵢ | R_θ)**

The gradient is:

**∇_θ L = Σᵢ Σₜ ∇_θ R_θ(sₜ⁽ⁱ⁾) - n · E_π[Σₜ ∇_θ R_θ(sₜ)]**

This is computed via backpropagation through the reward network.

### Challenges

- Non-convex optimization (local optima)
- Requires large amounts of demonstration data
- Loss of interpretability (what does the network reward?)
- Overfitting risk

### Solutions

- Use architectural priors (e.g., convolutional networks for image states)
- Regularization (weight decay, dropout)
- Pretraining on related tasks
- Ensemble methods for uncertainty

## Computational Complexity

IRL is fundamentally harder than RL because:

1. **Inner loop:** Each evaluation of a candidate R requires solving an RL problem (computing the optimal policy under R)
2. **Outer loop:** We must search over the space of reward functions
3. **Partition function:** In MaxEnt IRL, computing Z requires summing over all trajectories

For a state space of size |S|, action space of size |A|, and horizon H:

- Forward RL: O(|S|²|A|H) using dynamic programming
- IRL (Ng & Russell): O(|S|²|A|H · K) where K is the number of iterations
- IRL (MaxEnt): O(|S|²|A|H · T) where T is the number of gradient steps
- IRL (Bayesian): O(|S|²|A|H · M) where M is the number of MCMC samples

For large state spaces, we need function approximation and sampling methods, which add their own complexity.

## Summary of Approaches

| Method | Reward Form | Optimality Assumption | Output | Complexity |
|--------|-------------|----------------------|--------|------------|
| Ng & Russell | Linear wᵀφ(s) | Perfect | Point estimate | Medium |
| MaxEnt IRL | Linear wᵀφ(s) | Noisy (Boltzmann) | Point estimate | Medium |
| Bayesian IRL | Linear wᵀφ(s) | Noisy (Boltzmann) | Posterior | High |
| Deep IRL | Neural net f_θ(s) | Noisy (Boltzmann) | Point estimate | Very High |

## Open Problems

1. **Multi-modal rewards:** When the expert's behavior is consistent with multiple distinct reward functions, how do we represent this?
2. **Non-stationary rewards:** When the expert's values change over time
3. **Multi-agent IRL:** When multiple experts with different rewards interact
4. **Active IRL:** When the learner can query the expert for demonstrations
5. **Reward mis-specification:** When the expert is not actually optimizing any coherent reward (e.g., humans with biases)
