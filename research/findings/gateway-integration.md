# Paperclip ↔ OpenClaw Gateway Integration

Integration between Paperclip (agent runtime) and OpenClaw gateway, connecting the persistent agent to the orchestration layer.

## Architecture

- Paperclip server: localhost:3100 (embedded PostgreSQL, API-only mode)
- OpenClaw gateway: localhost:18789 (ws://)
- Adapter: `openclaw_gateway` with device auth (v2 format)

## Key Fix: Device Auth Protocol Version Mismatch

Paperclip's openclaw_gateway adapter (v0.2.7) uses v3 device auth payload format. OpenClaw gateway (v2026.2.15) only supports v1/v2 format.

**v2 format**: `v2|deviceId|clientId|clientMode|role|scopes|signedAt|token|nonce`
**v3 format**: `v3|deviceId|clientId|clientMode|role|scopes|signedAt|token|nonce|platform|deviceFamily`

Patched adapter to emit v2 prefix and omit platform/deviceFamily fields.

### Why disableDeviceAuth Doesn't Work

When no device object is sent, the gateway strips ALL scopes to empty (`scopes = []`). Every method authorization check fails with "missing scope: operator.write". Device auth is required to preserve scopes.

## Agent Config

```json
{
  "adapterType": "openclaw_gateway",
  "adapterConfig": {
    "url": "ws://127.0.0.1:18789",
    "scopes": ["operator.admin"],
    "headers": {"x-openclaw-token": "<gateway-shared-token>"},
    "autoPairOnFirstConnect": true,
    "devicePrivateKeyPem": "<auto-generated-ed25519-key>"
  }
}
```

## Issues Encountered

1. **"device signature invalid"** — v3/v2 protocol mismatch. Fixed by patching adapter.
2. **"missing url"** — PATCH accidentally overwrote full adapterConfig. User error.
3. **"missing scope: operator.write"** — disableDeviceAuth strips scopes. Must use device auth.
4. **"credit balance too low"** — Anthropic API billing issue, not integration.
