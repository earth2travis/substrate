# Process Guide: Writing UX Research Scenarios

## Summary

A step-by-step guide for writing UX research scenarios: when to use them (usability testing, concept testing, scenario-based design, diary studies, surveys) and when not to (card sorting, A/B testing, analytics review, stakeholder interviews, heuristic evaluation).

## Key Concepts

**Prerequisites Before Writing:**
Required: research questions, user profile, interface/concept to test. Strongly recommended: personas, top task list, stakeholder concerns, problem statements. Helpful: journey maps, support logs, analytics, prior findings.

**Seven-Step Process:**
1. List research goals (one or more per research question)
2. Identify activities and behaviors to observe
3. Draft scenario causing those activities
4. Remove interface clues (replace "Add to Cart" with "buy it")
5. Check for assumptions and leading language
6. Add necessary context, remove unnecessary backstory
7. Pilot test (read aloud, run real pilot session)

**Five Rules:**
1. Start with user's goal, not the feature you want to test
2. Strip out every word that appears in the interface
3. Tell participants to DO, not to DESCRIBE
4. Provide context, not instructions
5. Pilot test every time

**Templates:**
- Usability Test: Context + Motivation + Task + Optional Constraint
- Concept Test: Situation + Show Concept + Open-ended Prompt
- Diary Study: Trigger Condition + What to Capture
- Survey: Situation + Specific Question
- Exploratory: Broad Goal

## Applications

Scenario quality determines research validity. Good scenarios establish realistic goals with constraints that force real decision-making. Bad scenarios test reading comprehension by revealing navigation paths. Pilot testing reveals more problems than editing. [[process-philosophy]] [[a3-thinking]]
