# Research: GitHub Project Management

## Summary

Research on using GitHub's built-in tools (Issues, Projects, Labels, Milestones) to manage work for a two-person team. Key finding: keep it lightweight enough to maintain but structured enough to be useful.

## Key Insights

### Core Principle

GitHub's project management tools were built for software teams but work for any structured work. For a two-person team, the balance is critical: too much process kills velocity; too little loses context.

### Repository Structure

The research maps to:
- best-practices.md: general GitHub project management best practices
- issues-best-practices.md: how to write and manage great issues
- our-workflow.md: how the team should use these tools

### The Guide

The operational guide lives at `guides/github-project-management-guide.md`, which translates research into daily practice.

### Key Finding

The sweet spot for a small team is not in adding more tooling but in using existing tools with discipline. Issues as memory, labels as filters, milestones as goals, and projects as visibility.

## Synthesis

This research established the foundation for the team's GitHub operating model. The insights have been operationalized in guides, templates, and the Kanban doctrine. The ongoing work is in automation (Actions) and maintaining issue quality as the knowledge graph grows.
