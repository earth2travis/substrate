# Lean Software Development: Deep Research

## Summary

This research maps lean manufacturing principles from the Toyota Production System to software development. Mary and Tom Poppendieck's 2003 book "Lean Software Development: An Agile Toolbook" established the conceptual bridge, translating Taiichi Ohno's seven wastes to software: partially done work (inventory), extra features (overproduction), relearning (defects/correction), handoffs (transportation), delays (waiting), task switching (motion), and defects. The seven principles are: eliminate waste, amplify learning, decide as late as possible, deliver as fast as possible, empower the team, build integrity in, and see the whole. Key frameworks include David Anderson's Kanban Method (2010), the DevOps movement, continuous delivery, lean startup, and site reliability engineering. Modern trends include platform engineering as lean infrastructure, AI-assisted development, flow-based organizations, and software value stream management. The research also identifies what does NOT translate well: physical constraints vs logical flexibility, the human element in knowledge work, scale differences, and the fuzzier boundary between waste and necessary work in software.

## Key Claims

- Software development shares the same fundamental challenges as manufacturing: flow, waste, quality at source, and continuous improvement
- The average organization has 2–3x more WIP than it can process; each item increases lead time and waste risk
- Little's Law mathematically proves that reducing WIP reduces lead time: Average Lead Time = Average WIP / Average Throughput
- Platform engineering, AI-assisted development, and flow-based organizations are modern implementations of lean software principles
