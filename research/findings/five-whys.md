# The 5 Whys: Root Cause Analysis from Toyota

## Summary

The 5 Whys is a diagnostic technique that traces symptoms back to systemic causes through iterative questioning. Originated with Sakichi Toyoda, formalized by Taiichi Ohno, and industrialized inside the Toyota Production System. Older than Toyota: Plato's Meno uses repeated questioning. What Toyota added was cultural soil where honest answers were safe.

## Why It Works

TPS treats problems as signals, not nuisances. The two pillars create this culture:
- **Just in time**: pull system where demand drives production
- **Jidoka**: stop the line when something goes wrong; confront the problem while the cause is still visible

In this environment, the 5 Whys becomes a learning tool rather than a blame tool.

## Cultural Prerequisites

The technique fails when imported without the culture:
- **Genchi genbutsu**: managers go to where work happens, not conference rooms
- **Hansei**: honest self-reflection without deflection
- **Nemawashi**: consensus building before rapid implementation
- **Respect for people**: the question is "what allowed this to happen?" not "who messed up?"

## Complementary Tools

- **PDCA cycle**: the 5 Whys lives in Check/Act phases
- **Fishbone diagrams**: fan out across causes; 5 Whys drill into the best branch
- **A3 thinking**: captures full investigation on one page
- **Value stream mapping**: visualizes system flow to find where symptoms originate

## For Agent Systems

The same principle applies: when an agent makes a repeated error, asking "why" five times reveals whether the problem is in the prompt, the context, the tool, or the architecture. Surface problems, don't hide them.
